Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau’s algorithm evaluates a Bézier curve through repeated linear interpolation between neighboring pair of points. Given control points \(p_0, \ldots, p_n\) and some parameter \(t\) between 0 and 1, each step creates a new set of control points using

\(p_i' = (1-t)p_i + tp_{i+1}\).

This means each new point is \(t\) of the way from one control point to the next. Since every step reduces the number of points by one, repeatedly applying this interpolation eventually leaves a single point, which is the point on the Bézier curve corresponding to \(t\). In my implementation, evaluateStep performs exactly one of these levels: I loop through every pair of adjacent points, compute the interpolated point using the equation above, and store it in a new vector. Repeated calls to this function then produce the intermediate levels and eventually the final point on the curve. Part 2: Bezier surfaces with separable 1D de Casteljau

De Casteljau’s algorithm can be extended from Bézier curves to Bézier surfaces by essentially applying the same algorithm twice, once in each direction. Given an \(n \times n\) grid of control points and two parameters \(u\) and \(v\), I first treated each row of control points as its own Bézier curve and evaluated it at \(u\). This reduces each row to a single point. I then treated these points as another Bézier curve and evaluated it with \(v\), which finally gives a single point on the Bézier surface. In my implementation, evaluateStep performs one level of de Casteljau interpolation, while evaluate1D repeatedly calls it until there is only one point left. Finally, evaluate applies evaluate1D to every row using \(u\), then applies it one more time to the resulting points using \(v\). Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

To compute the area-weighted normal for each vertex, I traversed all of the triangles neighboring the vertex using the half-edge structure. In particular, I used h = h->twin()->next() to move to new triangles around the vertex until I returned to the starting half-edge. For each triangle, I obtained its 3 vertices to compute two edge vectors and added their cross product to a running sum. The direction of this cross product gives the face normal for the corresponding triangle, while its magnitude is proportional to the area of the triangle, so adding these cross products together automatically gives an area-weighted sum. After visiting all neighboring triangles, I normalized the resulting vector and obtain the final unit vertex normal.

Part 4: Edge flip

In my implementation, I first stored all of the half-edges, vertices, edges, and faces surrounding the edge being flipped. Since an edge flip does not create or remove any mesh elements, I reused these elements and reassigned their pointers to match the new configuration. In particular, I changed the two half-edges of the original shared edge to represent the new diagonal, then used setNeighbors to update the next, twin, vertex, edge, and face pointers of the six half-edges involved. I also reset the halfedge pointers of the affected vertices, edges, and faces. Before doing any of this, I checked whether either neighboring face was a boundary and returned the original edge if that was the case.

The most useful strategy for implementing this was drawing out the two triangles and labeling all six half-edges before and after the flip. I wrote down the two next cycles before changing any pointers, which made it much easier to see how the pointers should be reassigned. During debugging, I found it quite confusing when I wanted use a pointer but didn't know whether it was modified or not, so I made sure to store all of the original pointers beforehand. Part 6: Loop subdivision for mesh upsampling

To implement Loop subdivision, I first computed and stored the new positions of all of the original vertices and the new vertices. I did this before modifying the mesh so that all of the calculations were based on the original vertex positions. I then stored all of the original edges and split each of them once. For each split, I marked the inserted vertex as new and distinguished between the two halves of the original edge and the newly created edges. After all of the splits, I flipped each new edge connecting an old vertex to a new vertex. Finally, I copied the previously calculated newPosition values into the actual vertex positions.

One important debugging step in my experience was keeping track of the isNew flags carefully. Initially, I did not correctly mark the edges created by a split as new or old, which caused the wrong edges to be flipped and significantly deformed the mesh. This was not something that I easily noticed until I rechecked my 2 helper functions as well as the specs.

Effects of Loop Subdivision

After applying Loop subdivision, I noticed that the mesh became progressively smoother as the number of triangles increased. Sharp corners and edges became rounded/smoothed because the positions of the original vertices are replaced by weighted averages involving their neighboring vertices.

Pre-splitting edges near areas that I wanted to preserve reduced this effect because it added more vertices and edges around those parts, limiting the subdivision to stay closer to the original shape. Cube Symmetry

As seen through the images below, when I repeatedly applied Loop subdivision directly to cube.dae, the cube became smoother but also slightly asymmetric. Although the cube itself is geometrically symmetric, each square face has to be represented by two triangles, so the diagonals introduce an asymmetric composition. Loop subdivision operates on this triangle connectivity, so vertices with different local neighborhoods can be updated differently. After several iterations, these small differences become visible.

I was able to reduce this asymmetry by pre-processing the cube with edge splits before applying Loop subdivision. Specifically, I split the diagonal edge on each face of the cube so each face consists of four triangles. Adding these vertices made the connectivity around corresponding parts of the cube symemetric. After applying subdivision to this pre-processed mesh, the cube remained quite symmetric (see image below) because corresponding vertices had the same local neighborhoods and therefore received more similar subdivision updates.

Extra Credit: Boundary Support

For extra credit, I added support for meshes with boundaries. The main difference is that boundary vertices was treated differently from normal interior vertices. For a new vertex on a boundary edge, I simply use the midpoint of the two endpoints, and for an old boundary vertex I used v' = (3/4)v + (1/8)(v1 + v2), where v1 and v2 are its two neighbors on the boundary. I also had to ensure my edge split implementation to handle boundary edges was correct and make sure the boundary halfedges are still connected correctly after a split. Extra Credit 2: √3 Subdivision

I implemented √3 subdivision as another subdivision scheme besides Loop subdivision. Instead of splitting every edge like Loop subdivision does, I added a new vertex at the center of each triangle and connected it to the three original vertices, which splits one triangle into three. I then flipped all of the original interior edges and updated the positions of the old vertices using the √3 weighting rule:

\( v_{\text{new}} = (1-\alpha_n)v_{\text{old}} + \frac{\alpha_n}{n}\sum_{i=1}^{n}v_i \), \( \alpha_n = \frac{4-2\cos(2\pi/n)}{9} \)

where n is the valence of the vertex and v_i are its neighboring vertices.
